# ST-001 · A new developer can't run the project

**Type:** Incident / Build  **Severity:** Sev3  **Status:** not started
**Reporter:** Engineering manager  **Deadline:** before the new hire joins (end of this week)
**Impact:** every new developer loses hours; onboarding blocked; no one can confidently reproduce production locally.

## The problem

> "We're hiring a second backend developer next week. I asked a friend to try the
> README on a fresh laptop. The backend didn't start, and they gave up after 30 minutes.
> Also, someone told me the repo has a branch nobody remembers and a weird empty file.
> I want any new developer to go from `git clone` to a running backend and frontend
> in under 15 minutes, by following the README only."

Ask the manager (your mentor) clarifying questions if anything is unclear. Answers are given only when asked.

## Constraints

- Work on a branch. Never commit to `master`. Deliver through a Pull Request.
- If something used to exist in this repo, **recover it from history**; don't rewrite it from memory.
- Every dependency must be the one the code actually needs; prove it by running from a clean environment.
- Versions must be reproducible: two developers installing a month apart get the same versions.
- No secrets committed. A new developer must still know which settings exist and what the defaults are.
- The database must run without installing it directly on the laptop.
- Before deleting anything (files, branches), prove it's safe to delete and write that proof in the PR.
- Don't fix application bugs here, even if you find them. Write them down instead; they become other tickets.

## Acceptance criteria

- [ ] Fresh clone into a new folder → follow the README only → backend `/health` returns ok, `/locations` returns data, frontend shows destinations.
- [ ] Timed by you, start to finish, from the fresh clone. Write the time in the PR.
- [ ] README instructions match reality (no references to files that don't exist).
- [ ] PR contains: what was broken, why, how you found it, what you changed, blast radius.

## Proof to attach

- Terminal output from the fresh-clone run.
- The git commands you used to investigate history and the remote branch.
